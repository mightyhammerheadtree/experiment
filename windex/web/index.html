THE PARTS, NOT THE PRETENSE

One workspace. Distinct engines.

Windex assembles existing runtimes instead of inventing another CPU emulator.

Execution paths

Game folder → Wasm Wine → GEX translation + Linux ABI → WebAssembly / WebGPU

Linux ISO → v86 x86 PC emulator → real Linux kernel → console / 9P files

joelseverin/linux-wasm → native Wasm Linux kernel (research only, not integrated)

A Wasm Linux kernel is not an x86 translator. Connecting GEX to that kernel would require a new syscall, memory, loader and device integration—not a file concatenation.

Browser capabilities

What's required
GEX runtime package + GEX-compatible Linux/Wine filesystem trees and an initialized prefix. Linux console requires the v86, BIOS and ISO artifacts. Use python -m windex stage --help. The default shell contains no fabricated runtime or demo game.
Safety & licensing
Treat guest code as untrusted. Wasm/browser isolation is not a guarantee against malicious games or browser bugs. Imported files and game execution stay in the browser; the hosting server only serves assets. Persistent mode retains files in this origin's storage. Upstream licenses, corresponding-source requirements and game redistribution rights still apply. See the repository's Windex architecture documentation.
